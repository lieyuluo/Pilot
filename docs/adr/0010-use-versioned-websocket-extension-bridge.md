# 使用版本化 WebSocket 扩展桥接

本决策中的“人工持久配对”和旧版协议兼容策略已由 ADR-0015 取代；其余 WebSocket、安全边界、单连接和命令幂等决定继续有效。

JobPilot 保持 Node.js 24、TypeScript、Schema 驱动的单包工程，管理页面继续使用 REST 和 SSE；仅 Chrome 扩展页面执行通道新增一个监听 `127.0.0.1` 的版本化 WebSocket。连接必须通过固定扩展 Origin、人工持久配对和每次进程启动的短期挑战认证，并且全局只接受一个扩展实例、一个页面连接和一个串行批次；本机服务拥有全部批次状态，扩展命令携带唯一命令 ID、连接 ID、预期标签页、页面和截止时间，重复命令只返回缓存结果，不重新执行。真实发送把扩展协议和 Boss 适配器同时升级到版本 2；版本 1 扩展仍可连接并只读，但服务端拒绝发送并提示重新加载。扩展的点击实现完成后即可提前声明 `batch-send`，但在端到端实现与故障测试全部完成前，服务端仍拒绝建立发送会话和下发发送命令；隐藏管理页面入口不作为唯一闸门。该取舍引入双向协议与重连复杂度，以换取及时的页面状态报告、原子命令响应和 Manifest V3 Service Worker 生命周期适配，并取代 ADR-0006 中放弃 WebSocket 的决定。

## Consequences

- DOM 读取和站内导航只有在确认动作未开始时才可有限重试；发起沟通从开始执行起超时或断线即为结果未知。
- 心跳默认每五秒一次，十五秒无有效消息即解除页面连接；不可逆动作前要求批次页面处于活动且可见状态。
- 扩展升级、Boss 适配器版本变化、新页面连接或账号变化都会使只读校准和发送能力失效。
- 选择器随扩展打包，不远程下载代码或选择器；自动测试继续只使用本地夹具。
- 旧职位快照只保留历史展示，不生成真实发送防重事件；新账本按 `demo` 与 `boss` 来源隔离职位身份，并由平台当前状态兜底跳过已有沟通。
