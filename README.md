# JobPilot

JobPilot 是一个单用户、本机运行、有人值守的求职自动化控制台。首版仅适配 BOSS 直聘：按硬性规则排除职位，对其余职位发起沟通并发送预先确认的固定开场模板。

> 风险提示：真实页面自动化可能违反平台协议并导致账号限制。项目不绕过验证码、不规避风控、不模拟反检测；出现验证、风控提示、无法确认发送结果或连续三次失败时会停止并交由本人处理。

## 已实现边界

- 每批最多 20 次沟通成功或检查 200 个候选职位；每批均需人工确认启动。
- 规则只有“明确不满足才排除”，缺失或无法解析的值放行。
- 支持岗位关键词、城市/区域、最低薪资、最高经验、学历、公司/行业黑名单和发布时间。
- 发送结果不明时保存“结果未知”并立即停止，不自动重试。
- 只保存职位快照，不保存聊天正文或招聘者个人资料。
- 专用可见 Chromium 配置保存在用户应用数据目录；Cookie 和登录状态不参与导出。
- 异常截图保留 14 天；配置与职位快照可显式导出为 JSON。
- 自动化测试只使用本地 HTML fixture 和假平台适配器，从不访问真实 BOSS。

## 环境

- Windows 10/11
- Node.js 24 或更高版本
- 本人可正常使用的 BOSS 直聘账号

## 安装与本地演示

```powershell
npm install
npx playwright install chromium
npm run build
npm start
```

打开 <http://127.0.0.1:4317>。首次启动会创建一个默认停用的搜索方案和开场模板。先在“本地演示”模式中启用它们并运行一批，确认规则、状态和快照符合预期。

开发模式：

```powershell
npm run dev
```

## 真实页面启用流程

1. 在“搜索方案”和“开场模板”中完成配置并启用至少一项。
2. 在“设置”中选择“Boss 真实页面”并保存。
3. 点击“打开专用浏览器并只读校准”。若提示未登录，在打开的专用浏览器中由本人完成登录，再次点击校准。
4. 只读校准只检查登录、搜索和职位列表解析，不点击“立即沟通”。
5. 校准通过后，手动打开“解锁真实发送”并保存。
6. 回到总览，核对账号备注、方案和批次边界，再确认启动。

BOSS 页面会变化。当前选择器只经过本地 fixture 验证，第一次在真实账号使用前必须完成上述只读校准，并建议用低风险测试职位人工观察首批行为。

## 数据位置

默认目录为 `%LOCALAPPDATA%\JobPilot`：

- `jobpilot.db`：配置和职位快照；每次启动前备份到 `backups`。
- `browser-profile`：专用 Chromium 登录状态，不应复制、提交或分享。
- `evidence`：异常截图，启动时自动删除 14 天以前的文件。

可用 `JOBPILOT_DATA_DIR` 指定其他本机目录，例如：

```powershell
$env:JOBPILOT_DATA_DIR = 'D:\JobPilotData'
npm start
```

## 验证

```powershell
npm run typecheck
npm test
npm run test:e2e
npm run format:check
```

`test:e2e` 会先清理仓库内专用的 `.jobpilot/e2e` 目录，构建应用，然后仅通过本地假适配器完成浏览器场景。
