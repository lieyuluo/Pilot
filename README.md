# JobPilot

JobPilot 是一个单用户、本机运行、有人值守的求职自动化控制台。目标版本仅适配 BOSS 直聘：按硬性规则排除职位，对其余职位发起沟通并发送预先确认的固定开场模板。

当前里程碑已开放受限的真实批次发送：先完成只读校准，再由本人为当前 JobPilot 进程建立发送会话。最初每批只有 1 个沟通额度；累计 5 次无异常验证成功且待核实队列为空后，本机自动取得每批 20 个额度的完整资格。

> 风险提示：真实页面自动化可能违反平台协议并导致账号限制。项目不绕过验证码、不规避风控、不模拟反检测；出现验证或风控提示时会停止并交由本人处理。无法确认的单个发送会记为“结果未知”、永久阻止该职位自动重发并继续当前批次，等待本人事后核实。

## 已实现边界

- 验证批次最多 1 个沟通额度，取得本机完整资格后每批最多 20 个额度；每批最多检查 200 个候选职位，且均需人工启动。
- 规则只有“明确不满足才排除”，缺失或无法解析的值放行。
- 支持岗位关键词、城市/区域、最低薪资、最高经验、学历、公司/行业黑名单和发布时间。
- Chrome 扩展只连接本人明确选择的一个 BOSS 标签页；登录完全由本人操作。
- 扩展与本机服务使用用户主动授权、持久密钥和短期挑战认证；协议 v3 通过一次点击串行完成授权、页面连接与只读校准，旧版扩展必须更新。
- 每个联系人只执行一个持久化原子命令；不可逆步骤不自动重试，每次尝试后至少等待 5 秒。
- 永久账本只保存职位标识、消息摘要和状态事件，不保存聊天正文或招聘者个人资料；结构化动作诊断保留 14 天。
- Cookie、登录状态和 Chrome 配置文件均由 Chrome 自己保存，JobPilot 不读取或导出。
- 配置与职位快照可显式导出为 JSON。
- 自动化测试只使用本地 HTML fixture 和假平台适配器，从不访问真实 BOSS。

## 环境

- Windows 10/11
- Node.js 24 或更高版本
- 本人可正常使用的 BOSS 直聘账号

## 安装与本地演示

```powershell
npm install
npm run build
npm start
```

打开 <http://127.0.0.1:4317>。首次启动会创建一个默认停用的搜索方案和开场模板。先在“本地演示”模式中启用它们并运行一批，确认规则、状态和快照符合预期。

开发模式：

```powershell
npm run dev
```

## Chrome 扩展校准与真实批次

1. 运行 `npm run build`，确认生成 `dist/extension`。
2. 建议在 Chrome 中新建一个只用于本人求职的配置文件，并由本人正常登录 BOSS。
3. 打开 `chrome://extensions`，启用“开发者模式”，选择“加载已解压的扩展程序”，加载仓库中的 `dist/extension`。
4. 启动 JobPilot，并确认至少启用了一个搜索方案。
5. 在已经登录的 BOSS 标签页中打开扩展，点击“连接并检查当前页面”。这一次点击会在需要时授权扩展、连接当前标签页，并使用优先级最高的启用方案校准搜索列表与职位详情；完成后尽力返回搜索列表，不会点击沟通按钮。
6. 回到“总览”，选择方案并点击“启动批次”。首次启动会展示当前页面账号、模板、额度和待核实数量；确认后建立仅对本进程有效的发送会话。

BOSS 页面会变化。当前选择器只经过本地 fixture 验证；出现登录失效、验证/风控提示、页面结构未知或连接变化时，校准会失败并要求人工处理。

发送会话可以在页面顶部主动结束，关闭 JobPilot 进程也会失效。结果未知的职位必须在批次结束后先点击“打开并核对”，确认系统打开的是同一职位，再选择“确认已发送”“确认未发送”，或暂时不处理以保持未知。完整批次资格会永久保存在本机，但可在设置页主动重置。

## 数据位置

默认目录为 `%LOCALAPPDATA%\JobPilot`：

- `jobpilot.db`：配置、职位快照、发送资格、永久操作账本和短期诊断；每次启动前备份到 `backups`。

Chrome 配置文件、Cookie 和登录状态不在 JobPilot 数据目录中。

可用 `JOBPILOT_DATA_DIR` 指定其他本机目录，例如：

```powershell
$env:JOBPILOT_DATA_DIR = 'D:\JobPilotData'
npm start
```
